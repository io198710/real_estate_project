# Автоматизация обработки данных: рынок новостроек Москвы

Итоговый проект по курсу «Автоматизация обработки данных».

**Бизнес-задача:** по сделкам ДДУ из выписок (607 тыс. записей) оценить
предполагаемую цену ДДУ каждого лота и построить прогноз средней цены
кв.м на 2026 год.

Скрипт загружает данные, очищает их, проводит анализ (статистики,
временные ряды, ML-модели), строит отчёты (графики, PDF, Excel)
и сохраняет результаты в PostgreSQL.

## Установка

1. Python 3.10 или новее
2. Установить библиотеки:
   ```
   pip install -r requirements.txt
   ```
3. Положить Excel-файл «Отчёт_Пульс_Продаж_Новостроек_Москва_2025.11.xlsx»
   в папку `data/`
4. Создать базу PostgreSQL:
   ```sql
   CREATE DATABASE real_estate_db;
   ```
   Параметры подключения меняются в `config.py`

## Запуск

Полный пайплайн (все шаги по порядку, с логированием):

    python main.py

Каждый шаг можно запустить отдельно (по порядку):

    python 01_loading/load_files.py     - загрузка Excel -> CSV
    python 01_loading/validation.py     - валидация сырых данных
    python 01_loading/load_api.py       - курс валют из внешнего API
    python 02_cleaning/cleaning.py      - очистка данных
    python 03_analysis/analysis.py      - анализ, метрики -> output/metrics.json
    python 04_reports/reports.py        - графики, PDF, Excel
    python 05_automation/save_results.py - сохранение результатов в БД
    python 01_loading/load_database.py  - примеры SQL-запросов (JOIN, агрегаты)

Тесты:

    python 06_tests/tests.py

API с метриками (для систем бизнес-анализа):

    python 05_automation/api_server.py
    http://localhost:8000/metrics
    http://localhost:8000/health

## Регулярный запуск (Планировщик задач Windows)

Создать задачу — каждый день в 09:00 (путь укажите свой):

    schtasks /Create /TN "Недвижимость отчет" /TR "C:\путь\к\real_estate_project\05_automation\run.bat" /SC DAILY /ST 09:00

Проверить и удалить задачу:

    schtasks /Query /TN "Недвижимость отчет"
    schtasks /Delete /TN "Недвижимость отчет"

## Логика цены и признаки в ML-моделях

**Цена сделки** определяется по приоритету:
1. Цена по ДДУ (самая точная — фактическая цена сделки из выписки)
2. Цена по прайс-листу × медианный коэффициент скидки (~0.96: по сделкам,
   где известны обе цены, ДДУ в среднем на 4% ниже прайса, почти все
   укладываются в ±20%)
3. Медианная цена кв.м по рынку × площадь (задание: пропуски заполняем
   медианой)

**Регрессия (XGBoost)** прогнозирует цену кв.м — это и есть
предполагаемая цена ДДУ для лота без известной цены.

Признаки:
- `months_to_vve` — месяцы до ввода в эксплуатацию на момент сделки:
  ключевой фактор, на этапе котлована метр дешевле, чем после ВВЭ
- `Этаж` и `Комнат` — КАТЕГОРИИ (Label Encoding): первый/последний этаж
  дешевле средних, а 4-комнатная не в 4 раза дороже 1-комнатной
- `deal_year`, `deal_month` — дата сделки (рынок растёт)
- из справочника ЖК: стадия строительства, расстояние до МКАД,
  этажность, потолки, эскроу, тип каркаса, шоссе, отделка
- `Класс ЖК`, район, девелопер, ипотека, переуступка, тип объекта

**Классификация (XGBoost)** предсказывает переуступку (второй или
последующий владелец = перепродажа ДДУ до регистрации) по параметрам
лота и сделки — индикатор спекулятивного спроса.

**Прогноз 2026** — сглаживание Хольта-Уинтерса (тренд + сезонность)
по помесячной средней цене кв.м за 2014-2025.

## База данных

PostgreSQL 17 установлен локально (данные лежат в
`C:\Program Files\PostgreSQL\17\data`).

Подключение (настройки в `config.py`):

    host:     localhost
    port:     5432
    database: real_estate_db
    user:     postgres
    password: postgres

Посмотреть базу можно в pgAdmin
(`C:\Program Files\PostgreSQL\17\pgAdmin 4\pgAdmin4.exe`, сервер
PostgreSQL 17 -> Databases -> real_estate_db) или через psql:

    "C:\Program Files\PostgreSQL\17\bin\psql.exe" -U postgres -d real_estate_db

После запуска пайплайна создаются таблицы:

- `deals` — очищенные сделки ДДУ (547 тыс. строк)
- `zhk` — справочник жилых комплексов (стадия, срок ВВЭ, МКАД)
- `analysis_results` — метрики анализа

Пример запроса с JOIN и агрегатами:

    SELECT d.district, COUNT(*), ROUND(AVG(d.price_sqm))
    FROM deals d
    JOIN zhk z ON d.id_zhk = z.id_zhk
    GROUP BY d.district
    ORDER BY 3 DESC;

## Отправка отчётов по email

Настраивается в `config.py` (SMTP_SERVER, SMTP_USER, SMTP_PASSWORD, EMAIL_TO).
Для Gmail нужен «пароль приложения».
Если настройки не заполнены — письма не отправляются, всё остальное работает.

- `report.xlsx` — Excel-отчёт
